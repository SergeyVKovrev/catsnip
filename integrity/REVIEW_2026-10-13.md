## Independent critique of the Perplexity example

Its sample checker is **not compatible as written** with the existing snapshot:
1. It expects raw canonical TSV as the manifest, but ours is a Markdown table with prose.
2. Its invocation arguments and path base do not match the current checker; it derives paths relative to `agent-field/` rather than the project-root paths in the manifest.
3. It silently skips symbolic links, potentially hiding anomalous directory entries.
4. It does not establish an independently pinned full Markdown hash.
5. It has no verified execution result in the supplied external report.

These are source-inspection findings, not evidence of wrongdoing.

## Remaining security gaps

- `main` is unprotected in current connected GitHub readout; observed commits are unsigned. No independent signed approval chain or independent append-only witness has been configured.
- The updated verifier itself can be altered by anyone with sufficient repository write access. Verify its source against an independent trusted copy/digest, or execute a trusted standalone verifier.
- A local directory can change during checking (time-of-check/time-of-use); verify a frozen checkout/immutable archive, or move to more rigorous handle-based readers where warranted.
- We have not built or empirically validated a directory-level Merkle tree, transparency service, signed state manifests, anti-rollback ledger, or mandatory pre-write CI protection. Future nested directory snapshots require explicit canonical versioning and new externally pinned roots.
- A changed file size or SHA-256 means **difference**, not automatically malicious action or attribution.
- Source commit timestamps and repository-local copies do not prove provenance or freshness.
